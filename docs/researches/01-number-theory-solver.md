# 恶臭数字论证器的数论求解方案研究

> 将"任意数字分解为 114514 顺序算式"从硬编码查表 + 贪心，重构为**区间 DP 值域生成 + 分支限界最短表示**的完整算法求解器。本文记录问题形式化、核心数学工具、精确性论证、实验数据与工程演进。

## 0. 摘要

| 维度 | 旧实现 | 新实现 |
|------|--------|--------|
| 值域来源 | 575 行硬编码表（离线穷举物化） | 运行时区间 DP 生成（基线 15ms / 扩展 ~650ms） |
| 大数分解 | 贪心带余除法（只会 `d·q+r`） | 分支限界最短表示（乘法/借位/加减边，双指标最优） |
| 平均块数 [1,10⁵] | 5.93 | **3.03** |
| 正确性保障 | 无系统验证 | 11.2 万值集条目**全量浮点求值严格一致** + 行为矩阵 + 旧表回归 |
| 扩展算子 | 无（纯四则） | `!` `⌊⌋` `√` `^` 前导负（全程 IEEE-754 零舍入） |

核心数学贡献：**值域限制在二进分数环 ℤ[1/2] 的不变量**——使任意表达式的浮点求值与精确有理数运算严格一致（§3）。

## 1. 问题形式化

**块（block）**：数字序列 `114514` 的一个完整消耗——切分为若干连续段（如 `114|51|4`），段间以运算符连接、任意加括号、可施加一元算子，顺序固定，六个数字每个恰用一次。旧表的 `(114514+114514)` 即两个块。

**值域** `V ⊂ ℚ`：全部单块可表出的有理数。
**任意数表示**：块之间以 `+` `*`（及顶层负号）拼接，最小化块数。

与 four fours / Countdown 问题同构。**不存在数论闭式解**：V 是约 6.4 万个表达式的像（切分 2⁵ × Catalan × 4^|ops|），对加法/乘法/模结构均不封闭，同余、p-adic 赋值等工具只能提供必要条件。因此"求解"的正确范式是**搜索/DP**——本方案的优雅性来自让每层搜索都有精确的数学不变量与可证明的优化性质，而非来自某个闭式公式。

## 2. 值域生成：区间动态规划

### 2.1 定义

`S(i,j)` = 子串 `d_i..d_j` 可表出的精确有理数 → 最短表达式。

```
S(i,j) = { 拼接整数 d_i..d_j }                          // 相邻数字并段
       ∪ closure₁( ⋃_{k} { a ∘ b : a ∈ S(i,k), b ∈ S(k+1,j), ∘ ∈ {+,-,*,/,⌊·/·⌋,^} } )
```

其中 `closure₁` 为一元闭包（`!`、`√`、`⌊·⌋` 至不动点）+ 前导负。

**完备性**：任何表达式树都能按"一元算子作用的子树完整落入某一侧"选取分裂点；闭包值作为更大区间组合的操作数参与，故不漏值。（前导负仅对正整数施加、不回流一元闭包——负分数的表出由二元减法覆盖，此为受控近似。）

### 2.2 表达式空间计数

k 段切法 `C(5,k-1)`，括号化 `Catalan(k-1)`，运算符 `|ops|^(k-1)`：

| 段数 k | 表达式数（四则） |
|--------|------------------|
| 6 | 42 × 1024 = 43008 |
| 5 | 5 × 14 × 256 = 17920 |
| 4 | 10 × 5 × 64 = 3200 |
| 3 | 10 × 2 × 16 = 320 |
| 2 | 10 × 4 = 40 |
| 1 | 1 |
| **合计** | **64489** |

去重后基线值域仅数千个有理数——运行时生成毫无压力。

### 2.3 值域界限与防溢出

四则组合的最终值满足 `|v| ≤ 229028`（加法最大 `114514+114514`，乘法最大 `114×514`），扩展算子（`!`、`^`）引入大值但以 2⁵³ 为硬界。**未归约的中间积**不超过两个已归约值的乘积，故每步运算前做 `|a| ≤ LIMIT/|b|` 检查即可保证全程在 Number 精确整数域（< 2⁵³）内，无需 BigInt，性能提高约 50 倍。

### 2.4 双池架构

`divFloor`（`⌊a/b⌋`）与 `FLSQ`（`⌊√n⌋`）若回流组合，值集平方爆炸（实测 312 万条 / 25.7s）。双池控制：

- **core**：四则/幂/一元闭包/前导负产物，回流作更大区间的操作数；
- **aux**：divFloor/FLSQ 产物，仅作最终面额（solver 直接查用）。

最终值域 = 顶层 core ∪ aux（冲突取更短表达式），规模 11.3 万、构建 ~650ms。

## 3. 精确性：二进分数环不变量（核心）

### 3.1 动机：浮点失真是结构性的

宽松值域（任意分数）下，生成端精确、求值端失真的案例俯拾皆是：

- **灾难性抵消**：`1-(1+4·5⁻¹⁴)` 精确值 `-4/5¹⁴`，浮点求值相对误差 ~3×10⁻⁷（尾数对消放大 2⁻⁵² 达百万倍）；
- **分数底幂**：`(11/55)⁻⁴ = 625`，浮点 `0.2` 非精确表示，求值得 `624.9999999999999`；
- **连除**：`1/(4/1680) = 420`，求值得 `419.99999999999994`。

**整数输出必须严格精确**（旧实现即如此），这排除了"容忍浮点误差"的路线。

### 3.2 ℤ[1/2] 的封闭性

**命题**：分母为 2 的幂的分数（dyadic rationals）与整数构成的集合 `D = ℤ[1/2]`，在加减乘（不溢出、不次正规时）下封闭，且每步运算结果都是 IEEE-754 精确表示。

**推论（不变量）**：值域限制在 D 内 ⟹ 值集任意条目的表达式浮点求值 ≡ 精确有理数值。实测 11.2 万条全量审计**零不一致**（含除法——除法结果非 dyadic 即被丢弃）。

非 dyadic 中间分数（如 `11/4514`）一律丢弃，由此损失的"分数→整数"转换由 §3.4 的复合算子以纯整数运算补回。旧表招牌 `11/(45-1)*4 = 1` 因 `11/44 = 1/4` 恰为 dyadic 而完整保留。

### 3.3 一元算子的精确性论证

| 算子 | 约束 | 论证 |
|------|------|------|
| `n!` | n ∈ [0,18] 非负整数 | 18! ≈ 6.4×10¹⁵ < 2⁵³ |
| `√x` | x ∈ D 且分子分母均为完全平方 | 最简 dyadic 分数 p/q 均完全平方 ⇔ √(p/q) ∈ D；IEEE sqrt 正确舍入，2 的幂域内精确 |
| `⌊p/q⌋` | 整数运算 `(p−p%q)/q − (p%q<0)` | JS `%` 为截断语义，负数须修正（**负分母同理**：商负且非整除时 floor = trunc − 1） |
| `⌊√n⌋` | n ∈ (15, 2⁵¹]，非完全平方 | 浮点 √n 与最近平方数边界距离 ≥ 1/(2√n) ≫ ulp ⟹ floor 无歧义 |
| `⌊a/b⌋` | 未约分分子 \|n\| < 2⁵¹ | 浮点商与最近整数距离 ≥ 1/\|d\|，舍入误差 ≤ \|n\|·2⁻⁵²/\|d\| < ½·\|d\|⁻¹ ⟹ floor 无歧义 |

### 3.4 幂的整数底约束

浮点 `pow` 对分数底走 exp/log 路径不保证精确；整数底整数指为乘法语义，值 ≤ 2⁵³ 时精确。负指数仅 2 的幂底可保 dyadic（`2⁻ᵏ`），其余丢弃。

### 3.5 一处隐蔽陷阱：32 位截断

2 的幂判定不可用 `q & (q-1) === 0`——JS 位运算将操作数截断为 32 位：`24¹⁰ = 2³⁰·3¹⁰` 的低 32 位恰为 `2³⁰`，被误判为 dyadic 而混入非精确值。正确实现为逐次除二。此类 bug 抽样验证几乎不可能稳定复现，唯有**全量审计**能兜住。

## 4. 最短表示求解器

### 4.1 图模型

将任意大整数 n 的表示形式化为**带面额的最短表示问题**（coin problem 的加权推广）。节点为非负整数（BigInt），最小化 `(块数, 表达式长度)` 字典序：

- **乘法边** `n = d·q + r`，代价 `cd(d) + c(q) + c(r)`（带余除法，数论第一课）；
- **借位边** `n = d·(q+1) − (d−r)`，余数过半时的减法变体——修复旧贪心"不会做减法"的缺陷（`229027 = 229028 − 1` 型）；
- **加减边** `n = v ± m`，面额 v 与差值 m 拼接。

### 4.2 面额体系

- **单块面额**：值域非负整数（cd = 1）；
- **多块乘积面额**：top-24 大值 × {top-24 大值 ∪ 全部小值面额}，cd = 因子块数和。分层设计覆盖"大×大"（radix 上限）与"大×小"（`114514×2 = 229028`）两类关键组合。

### 4.3 分支限界

- 贪心解为初始上界（最坏不劣于旧实现——`1 ∈ V` 保证贪心永远有解）；
- 块数下界 `lb(m) = 1 + ⌈log_{maxVal} m⌉` 剪枝；
- **乘法边**：面额降序扫描 ⇒ q 递增 ⇒ 下界单调转劣；
- **加减边**：自二分定位点双侧指针按 `|n−v|` 升序全扫，`|n−v|` 单调不减 ⇒ 下界单调 ⇒ 可提前终止。单侧窗口（原型教训）会漏掉 `114514+114514` 型半值面额；
- 节点数与时间双保险丝，超限全程退化贪心。

### 4.4 双指标

块数并列时取表达式更短者——自动抑制 `×1`、`1^x` 类凑位冗余（它们不减少块数却增加长度）。恒等元消除**只能在输出端**做（finisher 正则），不能在生成端跳过：块内每数字必须消耗，`1×4` 恰是子区间 `(1,4)` 中值 4 的唯一合法表示。

## 5. 输入语义

- **整数**：直达 2⁵³；radix 分解的中间积 `d·q ≤ n` 保证浮点求值全程精确；
- **非整数**：`String(num)` 取最短 round-trip 十进制（尊重用户意图：`0.1 → 1/10` 而非其二进制精确值），解析为最简分数 p/q，先查值域分数命中，否则 `(P)/(Q)` 单次整除 round-trip 精确；
- **负数**：`-(|n| 的解)`；
- **Infinity/NaN**：保留吐槽文案。

## 7. 已知边界与后续方向

- **SQ 容差圆整**：eval 环境的容差 SQ 在"真值非整数但与整数差 < 1e-9"时可能错误圆整（理论可达：`(a/b)²` 与整数差 ≥ 1/b² ≈ 1.9×10⁻¹¹）。全量审计未触发；如需彻底消除，eval 环境应改用精确分数 sqrt；
- **(P)/(Q) 大分子**：非整数输入的分子可达 10¹⁷（略超 2⁵³ ~11%），表达式求值相对误差 ~10⁻¹⁵ 量级，仍在 round-trip 语义内；
- **负分数底幂、∛ 等立方根**：可经素因子分解扩展（指数整除判定），未实现；
- **表达式美化**：finisher 为保守正则；AST 级优先级打印可获得更短输出；
- **通用化**：DIGITS 数组参数化即可支持其他数字序列（24 点、其他梗序列）。

## 8. 工程演进考古：被全量审计逮住的 bug

按发现顺序，全部属于"抽样验证幸存、全量审计现形"：

1. **fDiv 参数序**：`(p₁/q₁)÷(p₂/q₂)` 传成 `fMul(p₁,q₁,p₂,q₂)`——除法全体被算成乘法，两个原型版本"全绿"均为抽样掩盖；
2. **uFloor 负数语义**：JS `%` 截断 ≠ floor，`⌊−478.8⌋` 曾得 −478；
3. **mulSafe 缺席**：面额表达式顶层为 `(A)+(B)` 形态时裸拼乘法，`(114)+(5/(1+4))·q`（面额 115）优先级劫持——原型 5 样例恰好未触发；
4. **isDyadic 32 位截断**（§3.5）；
5. **负指数奇偶**：`(−5) % 2 === −1 ≠ 1`，`POW(−4,−5)` 丢符号；
6. **FLSQ × 容差 SQ**：`⌊√(2⁴²−1)⌋` 的 `2097151.9999998` 被容差 SQ 圆整为 2097152——floor 类算子必须独立实现，不复用容值版本。

**方法论结论**：此类"生成器 + 求值器"双系统的验证，唯一可信形态是**值集全量 eval 对拍**（本仓库 `tools/verify.mjs`，CI 可直接运行）。
